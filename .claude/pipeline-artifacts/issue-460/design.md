# Design: Upload cost-breakdown.json as GitHub Actions artifact for cross-machine optimization

## Context

Each pipeline run currently produces `.claude/pipeline-artifacts/cost-breakdown.json` (generated by `cost_generate_breakdown` in `scripts/sw-cost.sh:667-691`). That file feeds local optimization machinery — `baseline_update_from_breakdown` (`scripts/lib/cost/baselines.sh:153`), UCB1 model routing, and the cost-aware template — but it never leaves the machine that produced it. Each CI runner starts with empty baselines, so cross-run learning is wasted.

The workflow already uploads a catch-all `pipeline-logs-issue-<N>-run-<run_id>` artifact (`.github/workflows/shipwright-pipeline.yml:1244`), but:
- retention is 7 days (too short for trend baselines),
- the name is run-scoped (no prefix you can glob on),
- the payload is a fat tarball with logs and event streams mixed in.

Constraints:
- Bash 3.2 compatibility (no `declare -A`, no `readarray`).
- `set -euo pipefail` everywhere; atomic writes via tmp+`mv`.
- `gh` CLI is present on runners and dev setups; honour `NO_GITHUB`.
- Default pipeline behaviour must not change — cross-machine reads are opt-in.
- One known related failure exists in memory: prior incident around duplicate/colliding `upload-artifact` steps in this workflow. The fix must not collide names with the existing catch-all, and must not turn into a second drift-prone upload site.

## Decision

Add a **dedicated, minimal `upload-artifact@v4` step** for `cost-breakdown.json` only, with a queryable name and 90-day retention. Pair it with a **leaf-level shell helper** that downloads matching artifacts on demand via `gh api` / `gh run download` and merges them into local baselines. Bootstrap is **opt-in** (`SHIPWRIGHT_BOOTSTRAP_BASELINES=true` / `--bootstrap-baselines`); upload is automatic.

Key design moves:

1. **Schema versioning at the source.** `cost_generate_breakdown` adds `schema_version: 1` to the JSON. Every downstream consumer (fetch helper, doctor) gates on this field — additive today, the extension point for future shape changes.
2. **Dedicated upload step, not consolidation.** The new step lives next to the existing catch-all at `shipwright-pipeline.yml:1244` (both guarded `if: always() && steps.claim_check.outputs.skip != 'true'`, both `continue-on-error: true`). Two narrow steps with disjoint purposes is preferable to one fat step or refactoring the catch-all (which is forensic / failure-debugging by design and has different retention semantics). This is the explicit lesson from the prior duplicate-upload incident: keep purposes separate; uniqueness comes from `${{ github.run_id }}-attempt-${{ github.run_attempt }}` suffixing.
3. **Leaf helper module.** `scripts/lib/cost/artifact-fetch.sh` is a new sibling to `baselines.sh`, `iteration.sh`, `stage.sh`, `table-render.sh`. It depends *down* on `baselines.sh` (calls `baseline_update_from_breakdown`); nothing in `baselines.sh` calls back up — no circular dependency. `gh` is injected as `_GH_BIN`, so tests shim it.
4. **Idempotent merge.** `~/.shipwright/baselines/.fetched-runs.json` records merged `run_id`s. Re-running fetch is a no-op. This matters because `baseline_update_stage` uses an EWMA — double-merging would skew the smoother.
5. **Three error tiers, none of which fail the pipeline.** Missing `gh` → soft warn, return 1. Rate-limited / 403 → skip artifact, continue. Schema mismatch → record reason, skip. The new upload step itself is `continue-on-error: true` so a 5xx from GitHub never breaks merge gating.

```yaml
# .github/workflows/shipwright-pipeline.yml — after existing catch-all (line ~1255)
- name: Upload cost-breakdown.json (cross-run baselines)
  if: always() && steps.claim_check.outputs.skip != 'true'
  uses: actions/upload-artifact@v4
  with:
    name: cost-breakdown-issue-${{ github.event.inputs.issue_number || github.event.issue.number }}-run-${{ github.run_id }}-attempt-${{ github.run_attempt }}
    path: .claude/pipeline-artifacts/cost-breakdown.json
    retention-days: 90
    if-no-files-found: ignore   # early-failure runs may produce nothing
  continue-on-error: true
```

Invariants enforced by types/names:
- Artifact name uniqueness: `(issue, run_id, run_attempt)` triple — collisions impossible without re-running the *same* attempt.
- Schema gating: any consumer that does not `jq -e '.schema_version == 1'` is a bug.

### Data Flow

1. **Generate (every run).** `cost_generate_breakdown` writes `cost-breakdown.json` with `schema_version: 1` atomically to `.claude/pipeline-artifacts/`.
2. **Upload (CI only, every exit path).** New `upload-artifact` step uploads under `cost-breakdown-issue-<N>-run-<run_id>-attempt-<a>`; `if-no-files-found: ignore` covers early-failure runs; `continue-on-error: true` covers GitHub flake.
3. **Discover (opt-in).** A future run on a different machine sets `--bootstrap-baselines`. During intake, `sw-pipeline.sh` calls `cost_fetch_remote_breakdowns "issue:${ISSUE_NUMBER}" 10` then `cost_fetch_remote_breakdowns "all" 20`.
4. **Filter.** Helper calls `gh api /repos/{o}/{r}/actions/artifacts?per_page=100`, filters by name prefix client-side (REST API doesn't support server-side globs), excludes IDs in `.fetched-runs.json`.
5. **Download + validate.** For each match: `gh run download --name <name>` into a temp dir; `jq -e '.schema_version == 1'`; on failure record `skipped:schema_mismatch`.
6. **Merge.** Pass file to `baseline_update_from_breakdown`. On success, append `run_id` to `.fetched-runs.json` (atomic tmp+mv).
7. **Emit.** Event `cost.artifact_fetched` with merge counts feeds the events stream for downstream observability.

### Error Boundaries

| Boundary | Caught by | Behaviour |
|---|---|---|
| `gh` missing / unauthenticated | `cost_fetch_remote_breakdowns` precondition | Return 1, `warn`, do not fail the pipeline. |
| `NO_GITHUB=1` set | Same precondition | Skip silently, return 0. |
| `gh api` 403 / rate-limited | Per-artifact loop | `warn`, skip artifact, continue. Honour `X-RateLimit-*` headers if present. |
| `gh api` 5xx | Per-artifact loop | Skip with warn; helper is best-effort. |
| Downloaded JSON missing / not JSON | Per-artifact validation | Record `skipped:invalid_json`, continue. |
| `.schema_version != 1` | Per-artifact validation | Record `skipped:schema_mismatch`, continue. |
| `baseline_update_from_breakdown` non-zero | Per-artifact merge | Record `skipped:merge_failed`, continue. |
| New upload step fails in CI | `continue-on-error: true` | Run still succeeds; doctor catches structural drift. |
| Concurrent re-run race | `run_id` + `run_attempt` suffix | Names are unique by construction. |
| Doctor check misses regression | `shipwright doctor` grep for `cost-breakdown-issue-` in workflow | `check_warn` (not error) — non-fatal advisory. |

## Alternatives Considered

1. **Use only the existing catch-all `pipeline-logs-*` artifact (line 1244).**
   *Pros:* zero workflow changes. *Cons:* 7-day retention is too short for trend baselines; name is run-scoped (no prefix glob); consumers must download and untar a fat bundle to fish out one JSON. Rejected.

2. **Push `cost-breakdown.json` to an orphan branch** (mirroring `ruflo_ci_memory_push` at line 1239 and `sw_discovery_ci_push` at line 1093).
   *Pros:* survives indefinitely. *Cons:* git push is slow; another orphan branch to GC; cost data is per-run and Actions Artifacts is the right storage primitive. Orphan branches are correct for *append-only memory*, wrong for per-run snapshots. Rejected.

3. **PR comment summary + artifact** (issue's option 3).
   *Pros:* human-visible. *Cons:* PR comments rot, aren't machine-parseable, add API noise. Useful but orthogonal — deferred as stretch (Task 13 in the plan), out of MVP scope.

4. **Consolidate into the existing catch-all step** (single upload with both 7-day and 90-day retention via duplication).
   *Pros:* one fewer step. *Cons:* `upload-artifact` doesn't allow split retentions per file; bloats the catch-all bundle; and directly hits the prior failure pattern of duplicate/colliding `upload-artifact` configurations. Rejected — keep purposes separate.

## Implementation Plan

**Files to create:**
- `scripts/lib/cost/artifact-fetch.sh` — `cost_fetch_remote_breakdowns`, `cost_list_remote_breakdowns`, `_GH_BIN` injection, Bash 3.2 compatible, atomic writes (~120 lines).
- `scripts/sw-cost-artifact-test.sh` — `gh` shim + five test cases (list, fetch+merge, schema mismatch, idempotency, missing `gh`) (~150 lines).

**Files to modify:**
- `.github/workflows/shipwright-pipeline.yml` — add the dedicated upload step after line 1255 (immediately after the existing catch-all).
- `scripts/sw-cost.sh` — (a) inject `schema_version: 1` into the `jq -n` block at lines 667–691; (b) `source` `artifact-fetch.sh` near the other `lib/cost/*.sh` sources; (c) add `breakdown-fetch <filter> [limit]` subcommand parallel to existing `breakdown`.
- `scripts/sw-pipeline.sh` — add `--bootstrap-baselines` flag + `SHIPWRIGHT_BOOTSTRAP_BASELINES` env; gate `cost_fetch_remote_breakdowns` call inside intake stage. Default off.
- `scripts/sw-doctor.sh` — extend the cost block (~line 1029/1060) with two checks: (a) workflow contains `cost-breakdown-issue-`; (b) local `cost-breakdown.json` (if present) has `.schema_version`.
- `scripts/sw-cost-test.sh` — one assertion: `.schema_version == 1`.
- `package.json` (or test runner manifest) — register `sw-cost-artifact-test.sh` if not auto-discovered.
- `CLAUDE.md` — one-line entry under "Runtime State" listing the new artifact name.

**Dependencies:** None new. Uses `gh` CLI (already required), `actions/upload-artifact@v4` (already pinned), `jq` (already required).

**Risk areas:**
- **Concurrent same-issue runs:** mitigated by `run_id` + `run_attempt` suffix; impossible to collide.
- **Schema drift over time:** `schema_version` gate is the firewall; any consumer that omits the check is a defect.
- **GitHub API rate-limiting** during bootstrap on a fresh machine fetching N>20 artifacts: capped at 20 by default, 100 max; 403 is soft-failure; emits warn.
- **EWMA skew from double-merge:** prevented by `.fetched-runs.json`; helper is idempotent.
- **`pipeline-logs-*` dual-upload of the same file:** harmless (different purposes, different retentions); documented in the helper header.
- **Tests hitting real GitHub:** prevented by `_GH_BIN` injection + `PATH` shim, same pattern as `sw-pipeline-artifact-push-test.sh`.

## Observability — Monitoring Checklist

This change touches CI artifact upload + a leaf-level CLI helper; there is no live service or HTTP traffic to monitor. Substituted with **rollout monitoring** appropriate to this domain:

**P0 — first run after merge (immediate):**
- New upload step succeeds: Actions UI shows green `Upload cost-breakdown.json (cross-run baselines)` on the very first post-merge run.
- Artifact named `cost-breakdown-issue-<N>-run-<run_id>-attempt-<attempt>` appears in the run's Artifacts list with size > 0.
- Existing catch-all `pipeline-logs-*` upload still succeeds (no regression from sibling step).
- Pipeline gatekeeper still propagates exit codes correctly (the new step is `if: always()` and must not mask failures).

**P1 — first 24 hours:**
- Upload success rate ≥ 95% across runs (the remaining ≤5% being early-failure runs hitting `if-no-files-found: ignore`).
- No upload-step errors logged with `name already exists` — would indicate the run_id/attempt suffix logic broke.
- `cost-breakdown.json` size distribution roughly matches pre-change (no schema bloat).
- Doctor's two new checks pass on every dev machine that runs `shipwright doctor`.

**P2 — first 1–2 weeks:**
- First time a user runs with `--bootstrap-baselines`: fetch completes; `.fetched-runs.json` populates; `baseline_classify` transitions stages from `NEW` to classified.
- UCB1 model selection metrics: if the optimizer exposes "exploration vs exploitation" counters, exploitation share should increase on bootstrap-enabled runs vs cold-start.
- Artifact-creation-to-consumption ratio (uploads that get downloaded at least once): track via `cost.artifact_fetched` events. If it stays at zero indefinitely, the upload is unused and worth reconsidering.

### Anomaly Detection Triggers
- **Spike**: new upload step failure rate > 2× baseline in any 1-hour window → investigate (GitHub outage vs config regression).
- **Trend**: steadily rising rate of `skipped:schema_mismatch` over a 5-run window → schema drift sneaking in; gate harder.
- **Absence**: zero `cost.artifact_fetched` events from any machine for >2 weeks after release → cross-machine path is dead code; revisit.
- **Latency shift**: bootstrap-enabled intake time > 1.5× baseline intake time → fetch is too eager; lower default limit.

### Log Analysis
- Grep workflow run logs for `ERROR` / `FATAL` from the new upload step.
- Grep `events.jsonl` for `cost.artifact_fetched` (success path) and for any new `warn` lines emitted by `artifact-fetch.sh` (`gh missing`, `gh api 403`, `skipped:schema_mismatch`, `skipped:merge_failed`).
- Watch for retry storms from `gh api` (repeated 403/5xx in a single bootstrap run) — indicates rate-limit handling needs tightening.
- Watch for resource issues: artifact list response size > a few hundred KB suggests we should paginate more aggressively.

### Auto-Rollback Decision Criteria
Auto-rollback is **not applicable** in the live-service sense (no traffic). The analogous criteria:
- If the post-merge pipeline run fails outright due to the new step (despite `continue-on-error: true`), revert immediately — the YAML change is the suspect.
- If `>10%` of runs in the first day show schema mismatch warnings even though the producer was updated, revert: a fan-in coordination bug exists.
- If `--bootstrap-baselines` corrupts baselines on test users (regressions in `baseline_classify` outputs vs prior data), revert helper + delete `~/.shipwright/baselines/*.json` to recover.

Revert mechanics: workflow step is one block; helper file is one new file; both are individually revertable in separate commits if needed. No DB migration, no data loss path.

---

End of ADR. Plan is sound and matches the codebase as inspected; the only emphasis I'd add over the plan as written is that the prior duplicate-upload failure pattern explicitly *supports* keeping the new step separate from the catch-all rather than consolidating — separate purposes, separate retentions, uniqueness via `run_id`+`run_attempt` suffixing.
